  - an invalid `gh search` field in pr-watch

  - five more guard bypasses after round 1

- Verifiers checked claims against master and filed follow-ups ([#27](https://github.com/KrishP147/skills/issues/27), [#41](https://github.com/KrishP147/skills/issues/41), [#42](https://github.com/KrishP147/skills/issues/42)) instead of silently fixing scope.
- Mining past sessions corrected the tested-status table: `execution: pair` had been used 47 times, and the manager had run 50 times.

## What didn't

- The ledger timestamps were first estimated by the orchestrator and ran up to 1.5 h ahead. They are now re-stamped from git commit times. This is the exact failure the skill forbids, so it's a candidate hardening item: stamp times with `date` in the same command that writes the entry.
- The budget of 10 merges was overshot (13), because parallel loops were already in flight when it was reached. They were finished rather than abandoned.
- Implementers ignored "don't touch labels or comments" in about 4 runs: they moved `status:*` labels and commented on issues. One implementer test also targeted the real `~/.claude`, though the manager confirmed nothing changed.
- In [PR #32](https://github.com/KrishP147/skills/pull/32), the branch history held a fake credential shaped like an AWS key. It was squashed onto a fresh branch, so it never reached the remote.
- A PowerShell `[IO.File]` write with a relative path went to the main checkout instead of the worktree. It was caught and reverted before any commit.
- Worktree removal after each merge failed with "Permission denied" (the shell was still inside the folder). The folders were deleted separately.
